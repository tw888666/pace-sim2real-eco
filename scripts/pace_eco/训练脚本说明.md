# PACE-ECO 训练脚本说明

更新时间：2026-08-17 10:25 CST

## 统一规则

任务型 PPO（近端策略优化）、固定权重 PPO 和 PACE-ECO 的可比较训练现统一为：

- 4096 个并行环境；
- 从随机初始化开始；
- 统一执行 3000 次 PPO 更新；
- 统一使用最终检查点 `model_2999.pt` 做比较；
- GPU0 至 GPU5 均可手动选择；GPU5在2026-08-17服务器重启后已通过CUDA、Isaac Sim/PhysX和4096环境容量冒烟；
- 不自动查询或显示 GPU 型号、显存和利用率。

RSL-RL（强化学习库）的迭代编号从 0 开始。脚本传入
`--max_iterations 3000`，实际完成编号 0–2999 的 3000 次更新，最终生成
`model_2999.pt`。三个实验组都比较该最终检查点。

熵系数调度已随训练总长度从论文的 30000 次同比压缩为 3000 次：

- 初始熵系数：0.002；
- 最终熵系数：0.0005；
- turnover iteration（熵退火转折迭代）：2000；
- slope（斜率）：0.0025。

第 0、2000 和 2999 次更新使用的熵系数约为 0.001999932、0.00125 和
0.000510089。该调整保持原 30000 次调度在相对训练进度上的形状，而不是只移动
转折点。

所有脚本使用以下 GPU 映射：

```text
脚本参数中的物理 GPU 编号 -> CUDA_VISIBLE_DEVICES -> 进程内 cuda:0
```

修改物理 GPU 编号不改变任务、环境数、训练次数或超参数，但不同硬件和并行归约可能
令最终权重产生数值差异，不能保证逐位一致。

## 长训练必须使用可恢复终端会话

超过 1000 次更新的训练必须在 tmux（终端会话管理工具）或 GNU Screen
（终端会话管理工具）内运行。公共脚本会检查 `TMUX` 或 `STY` 会话标记；若在普通
SSH 前台终端直接运行，会在启动 Isaac Sim 或占用 GPU 前退出，不会生成或修改模型
权重。正式评估不再强制使用持久会话，可以直接在普通终端运行。

本机已安装 tmux。运行超过 1000 次更新的训练前，先创建交互会话：

```bash
tmux new-session -s pace_train_gpu3
```

进入 tmux 后再粘贴训练脚本命令。临时离开使用 `Ctrl-b`，松开后按 `d`；重新连接
服务器后恢复会话：

```bash
tmux attach -t pace_train_gpu3
```

因为会话内保留的是交互 shell，训练结束后 tmux 会话仍然存在，直到手动执行 `exit`。

## 中断后继续训练

新训练若在完成 3000 次更新前被手动停止，可换一张空闲 GPU，从最近的检查点继续：

```bash
bash /home/xy.chen/tw/PACE-ECO/scripts/pace_eco/继续训练至3000次.sh 3 /home/xy.chen/tw/PACE-ECO/logs/rsl_rl/实验目录/model_2500.pt
```

续训脚本会从检查点目录读取原任务、种子、运行名、4096 环境数以及 PACE-ECO 预算，
不会要求再次手工填写这些训练参数。它会校验配置指纹；如果训练代码、环境、算法
超参数、预算或种子改变，则拒绝把不同实验拼接在一起。

恢复会保留策略、价值网络、优化器和算法检查点状态；PACE-ECO 还会恢复拉格朗日乘子
及其优化器。不过当前检查点不保存仿真器完整状态和所有随机数生成器状态，所以续训
不保证与一次不中断的训练逐位相同。正式结果优先采用不中断运行；该脚本主要用于
机器维护或意外中断后的恢复。

使用旧熵调度创建的运行不允许通过续训变成新调度权重。训练源码与算法配置改变后，
严格配置指纹会拒绝这种拼接；三组新协议权重必须从随机初始化开始。

本次新增 `calibration_v1` 与 `holdout_v1` 协议后，环境配置、重置模块和训练源码树
指纹已重新冻结。旧种子 0 权重文件没有被修改，仍可只读评估；但它们不再允许通过
`继续训练至3000次.sh` 恢复。正式种子 1–5 全部从随机初始化开始，因此不受影响。
